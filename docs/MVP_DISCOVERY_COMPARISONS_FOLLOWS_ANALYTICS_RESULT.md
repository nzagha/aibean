## Analytics semantics and limitations

Recorded **events** are deduplicated requests/actions, not unique visitors, conversions or verified humans. Anonymous browser beacons are abuse-bounded but not proof of human behavior. The browser receives only a signed HTTP-only/Lax cookie; production sets Secure. Session digests are not connected to User IDs. Content IDs are needed for scoped reporting. Selected filters are approved IDs/enumerated values plus `hasQuery`; free text is not stored. The fixed event/kind pairing and unrelated campaign checks execute server-side. Public Event records, legacy daily outbound counters, security rate budgets and independent Admin audit logs remain distinct models.

Reports include only the last 30 days (UTC), at most 500 aggregate rows. Writes prune up to 1,000 expired events and 1,000 analytics-prefixed throttle keys older than one day. Admin cleanup prunes up to 10,000 each with audit. **No scheduler is configured; physical expired rows may remain during inactivity or a large backlog until cleanup.** Other security throttle keys are untouched. A production cleanup schedule and privacy notice are operational release work, not an automatically configured service.

There is no attribution from arbitrary external UTM/referrer text, conversion calculation or claimed unique-visitor count. Existing outbound handlers still validate canonical destinations/safe URLs; analytics does not accept client redirect URLs. Recording/cleanup changes neither editorial approval, verification, rank nor paid-placement eligibility. Server actions reject another account even when the caller is an Admin.

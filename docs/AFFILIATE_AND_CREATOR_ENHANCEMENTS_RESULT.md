## Affiliate administration and attribution

`/admin/affiliates` provides Admin-only creation/editing of partner/program configurations, exact permitted destination hosts, HTTPS URLs, reviewed tracking templates, disclosures, Tool relationships and optional canonical campaign relationships. Programs have validity dates, optimistic revisions, immutable configuration snapshots and transactional audit reasons. Relationships preserve historical Tool/campaign/destination identity; create a new relationship instead of reassigning recorded clicks. Vendor/Creator cannot edit these Admin-managed destinations or receive capabilities through them.

All edits disable the affected program. Activation independently requires an exact **complete configuration SHA-256** in the private owner approval map and a verified provider-contract gate. These settings were not configured or changed. Proposed status is visible in the UI. No affiliate provider was contacted and no tracked commercial link was activated.

Existing `/outbound/[kind]/[slug]` POST controls remain canonical: same-origin protection, server-resolved published real Tool, no browser-provided URL. New campaigns must reference that Tool and remain public/eligible. Templates allow only fixed safe tokens plus `{click}`, `{tool}` and `{campaign}` query values; hosts are exact, with no wildcard, arbitrary redirect/return parameter, credentials, local IP, HTTP or executable URL. There is no server-side fetching of affiliate destinations; DNS ownership/resolution and partner destination behavior remain external verification responsibilities. Browser destinations are never accepted from requests.

Eligible affiliate routing requires the disclosure configuration hash rendered inside that CTA. Missing/stale disclosure, missing verified session, disabled/expired configuration or absent approval uses the ordinary Tool destination; invalid campaign context stops the request. An active affiliate request records a distinct click and does not increment ordinary outbound/organic-ranking events. Full configuration integrity is rechecked; configuration/attribution operations serialize through a short transaction advisory lock.

Click deduplication is one signed session/Tool/campaign/relationship per UTC minute. Limits: 30 eligible requests/session/minute and 1,000/Tool/minute. Budget rows are cleaned in bounded batches after one day. Stored clicks contain public entity/context IDs, minimized source enum, disclosure/config digest and a one-way dedup key; no account identity, IP, raw referrer, email, password or provider secret. These are **recorded requests, not unique visitors**. Creator reporting is restricted to owned campaigns; Vendor reporting requires actual ownership of the exact Tool. Reports aggregate recorded clicks over 30 days. Source/referrer labels remain coarse and do not prove an external campaign delivered a purchase.

Provider-neutral reconciliation accepts canonical HMAC-verified receipts from a privately configured verified adapter, with program/event/click identity, USD amounts, issuance no more than 24 hours old or five minutes into the future, and confirmed/reversed status. Admin authentication precedes verifier access and is rechecked in the transaction. Unsigned, stale, wrong-program/click, conflicting replay and invalid reversals fail. Duplicate identical receipts are idempotent; current conversion/commission totals use the latest retained receipt per click. Reversal is terminal for that click; a new purchase needs a separate attribution/receipt contract. Append-only receipts and audit preserve reversal history. No commission is calculated from click counts or proposed rates. Reports distinguish 30-day clicks from retained provider-reconciled commission history and do not claim payouts.

**New commercial recommendation, not an approved offer:** initial configurable target affiliate rate of **20% (2,000 basis points)** on eligible partner-confirmed revenue; actual partner contract may instead be fixed-rate or zero. Creator share defaults to **0%** under the Master’s aiBean-managed model and may be proposed per relationship from 0–100%. These values describe negotiation/proposals only; they do not auto-accrue money, promise revenue, grant ranking or operate a Creator payout system. Provider-confirmed amounts are authoritative. No real commercial value is assumed from an unconfigured provider.

## Creator presentation and campaigns

`/account/profile` adds structured headline/biography sections, allowlisted LinkedIn/YouTube/GitHub/Instagram/X/Bluesky links, approved owned avatar/cover image references and required alternative text. Existing base biography/website/handle editing and stable published handles are preserved. Presentation changes return the existing profile to private draft and reuse its request/review/publish/reject/suspend workflow. `/creator/profile/preview` is capability/owner scoped; Admin profile moderation displays the presentation for review. Public profile reads require published, eligible authors and omit images that subsequently become disabled/private/ineligible.

Images reuse the private resource inventory, approved PNG/JPEG/WebP MIME/signature/size and scanner/review controls. Selection requires clean, approved, owned image metadata attached to eligible public content. No arbitrary image URL or browser-supplied storage key is accepted. `/creator-media/[id]` checks current profile/campaign linkage, ownership or Admin preview authorization and public dependency visibility before private short-lived signed image delivery. Private Storage/scanner configuration and bucket verification remain mandatory. **No live upload/image provider was tested or activated.** The metadata references do not claim actual decoded image dimensions or bypass upload/scan review.

The existing resource editor contains an ordered campaign builder for canonical Tools, Skills, Playbooks, public Creator Stacks, Events, approved resource-page links, owned approved image blocks and text descriptions. Add/remove/up/down controls submit the actual ordered state; maximum 40 blocks and duplicate references are rejected. Existing content is referenced through real foreign keys, never copied into replacement content objects. Draft saves use parent-row revisions; concurrent edits accept one winner. Full base/presentation/block snapshots are append-only; owned campaign revision timestamps are visible and Admin audit provides decision reasons. Historical snapshot restoration is not an automatic database recovery operation.

Saving blocks unpublishes the campaign to draft. Submission and publication revalidate canonical dependencies. Private Creator/Admin preview routes show the current draft; published campaign pages retain the existing route and design. Owner unpublishing preserves content as a draft. Public reads dynamically omit unavailable/private/archived/canceled/suspended references and images after publication, preventing stale approval from leaking them. Structured campaign-to-Tool/Skill/Playbook relationships are validated by the existing behavioral analytics system. Public Tool CTAs carry the validated on-platform campaign context and current disclosure. Affiliate and ordinary engagement reports remain distinct. External resource-page links open their already moderated destination through the existing route; new video hosting/iframes/raw HTML are not introduced.

## Supported fit model

The existing comparison/ranking system remains unchanged. Additive fit inspection uses Master 24.6 starting weights: context 35%, exact recorded features 20%, recorded pricing 10%, ease 10%, reviewed verification 10%, completeness 5%, editorial 10%, less the recorded risk penalty. Explicit selected context assignments are averaged, supported features matched exactly after case/whitespace normalization, and pricing remains unknown when no fact is recorded. Verification requires a valid non-future, current date and verified status. Demo data is excluded from reviewed scores. Missing factors are omitted from the normalized partial score and the supported weight is displayed. **Ease of use remains unknown** because no approved fact field exists; no complete-fit recommendation, performance/reliability claim or fabricated review is produced. Inspection preferences are temporary and do not rewrite saved comparison context or organic ranking. Full evidence coverage requires reviewed factual inputs rather than invented numbers.
